# Standings projections and Main Event paths

The server derives these fields only after Reveal publishes all picks. PTS are authoritative banked points. PROJ retains those points and adds provisional grades from games in progress at their observed scores. Scheduled games and missing scores contribute no provisional points. Unresolved first scoring events are not guessed; missing halftime facts after halftime are not guessed from the later lead. NO_UPSET banks once. LEFT sums unresolved selection values, including overlapping or conflicting picks; it is **not** a jointly achievable maximum.

Main Event paths open only after all earlier-game propositions resolve or void. They enumerate candidate final scores within the application's 0–200 per-team range and combinations of remaining Main Event outcomes, preserving known first-score/halftime facts and score lower bounds. Winner and total come from the same score pair. Tied final scores and one-point scores are excluded. First scoring play minimum values and basic halftime feasibility constrain candidates. This is a bounded possibility model, not a full football scoring-sequence simulator or probability forecast. Examples can be unusual; cancellations, corrections, special scoring sequences and future rule changes can change feasibility. A no-path label is conditional on this model, not unconditional elimination.

The candidate scoring includes already banked points, all remaining Main Event selections, Manhattan score-prediction error and shared championships. No percentages or odds are invented. Once all Main Event propositions resolve, authoritative standings/finalization take over.

Outcome-equivalent candidates reuse point calculations. The API caches at most eight public contest boards per warm service instance, keyed by contest ID and persisted version; every version change recalculates. The privacy gate runs before cache access. Nothing is stored as authoritative projection data until the existing final snapshot workflow.
